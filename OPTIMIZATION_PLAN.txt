本轮执行顺序
============
01 [完成] 并行检查网关指标和初始化外部服务
   来源：feature/redeploy-and-probe-efficiency。
   涉及：指标状态、APISIX、Caddy、Swarm 初始化和 Docker Compose 预检审查。
   依据：网关指标检查和 APISIX、Caddy、Swarm 初始化仍按顺序等待。
   验证：配置预检、指标超时与部分结果、热重载取消路径的临时竞态用例，
   并使用同一条件的模拟上游复测 SIGHUP 后 HTTP 恢复。

   结果：预检、指标和生命周期用例连续 10 次通过竞态检测。三个模拟上游
   各延迟 800 毫秒时，HTTP 恢复从 2.526 秒降到 0.894 秒。
   审查结论：保留 Docker Compose 在镜像预拉取结束后的配置解析。
   镜像预拉取期间依赖的 env_file 可能被修改，删除旧容器前需重新读取。
   在模拟镜像拉取完成前移除 env_file，原改动发出了删除旧容器的请求。
   保留预检后，接口提前报错，未发出删除请求。该用例连续 10 次通过竞态检测。

   来源：feature/source-build-and-polling 的 4 个已验证提交。

   依据：当前基线仍逐路由扫描控制器，进程页隐藏时继续轮询，
   发布脚本通过改写 Go 源码注入版本。
   验证：OpenAPI 字节对比、进程轮询切换与卸载用例、发布脚本标签用例，
   以及隔离工作树中的 Linux、macOS、Windows 六目标构建与归档核验。

   结果：OpenAPI 字节对比通过。进程页隐藏与恢复、无标签和首标签发布
   用例通过。六个平台归档已逐一核对。

03 [完成] 收拢 Docker 和 Swarm 的日志请求选项
   涉及：pkgs/docker/logs.go、pkgs/swarm/service.go。
   依据：两类资源的快照和实时请求四次设置相同的输出、时间戳和缺省行数。
   做法：按 Docker SDK 日志协议复用已有 docker 包内的单一选项构造，
   容器检查 TTY、流读取和错误层级分别保留在原入口。
   验证：本地模拟 Docker API，核对四个入口的查询参数和返回行为。

   结果：四个日志入口的标准输出、错误输出、时间戳、tail 和 follow 参数
   及快照、流输出通过本地 Docker HTTP 模拟，连续 10 次竞态检测通过。

04 [完成] 简化 Gin 路由装配
   涉及：server/app/app.go 的 registerRoute。
   依据：五个常规 HTTP 方法逐一包装 Gin 的同一注册能力。
   做法：常规方法复用 RouterGroup.Handle，ANY 继续走 RouterGroup.Any。
   验证：注册方法、参数路由、索引和 ANY 行为，并对比 OpenAPI。

   结果：五种普通方法、路径参数、路由索引、ANY 的 HEAD/OPTIONS
   和普通路由不匹配 HEAD 均已验证。

05 [完成] 删除终端页面重复的连接收尾和不可达的重连分支
   涉及：本机 Shell 和 Docker 容器终端页面。
   依据：两页卸载时重复执行现有断开方法，shell 选择器在连接时禁用，
   change 回调只会在连接时工作。调用检索确认该回调只绑定于这些选择器。
   验证：连接后的选择器、主动断开、卸载，以及断开后建立新 shell 会话。

   结果：模拟组件覆盖连接、主动断开、断开后选新 shell 再连接、卸载。

06 [完成] 统一 Caddy 配置页的放弃修改确认
   涉及：Caddy 全局选项页、原始配置页和已有 helper/caddy.ts。
   依据：两页重复构造同一组文案、样式和确认操作。
   做法：复用同一份确认选项，页面各自负责脏检查、读取和保存。
   验证：未修改时直接读取，已修改时仅在确认后读取，文案及按钮属性一致。

   结果：原始和全局配置的读取时机及确认选项与基线逐项一致。
